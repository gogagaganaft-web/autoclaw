# Две группы прототипов: Диапазон и Список + стандартные placeholder (d/m/n_start/end, транслит)

## 1. Прототипы (`filter-prototypes.ts`)
Группы: **Диапазон** (была «Даты», поглощает «Числа») и **Список** (была «Справочники»).

**Диапазон — 5 прототипов** (коды типов не меняем — рендеринг цел):
| Код | Было | Станет | var по умолчанию |
|---|---|---|---|
| dateRange | Период дней: календарь | **Диапазон дат (календарь)** | d_start, d_end |
| range-days | Период дней: шкала | **Диапазон дат (шкала)** | d_start, d_end |
| dateRangeMonths | Период месяцев: сетка ·устар. | **Диапазон месяцев (календарь)** (снять legacy) | m_start, m_end |
| range-months | Период месяцев: шкала | **Диапазон месяцев (шкала)** | m_start, m_end |
| range-number | Числовая шкала | **Диапазон значений (шкала)** | n_start, n_end |

- range-number: новое поле **«Точность (знаков после запятой)»** — 0 = целые, 1–6 = дробные (влияет на формат шкалы и формат чисел в значении).

**Список — 2 прототипа:**
| Код | Было | Станет | var по умолчанию |
|---|---|---|---|
| multi-select-list | Справочник: список с поиском | **Список (поиск, чекбокс)** | транслит ключа поля строчными (например УК → uk) |
| hr-fond | Справочник: дерево целиком | **Список (иерархия)** | транслит ключа поля (ФОНД → fond) |

- select, multi-select/multi-select-fl (подключения), hierarchical-list, button-group — **legacy: true** (работают в существующих отчётах, но новые не создаются); select и подключения остаются «Список (одно значение/подключения)» в легаси-каталоге.
- `defaultVarNames`: диапазоны → d/m/n_start+end по типу; списки → `translit(field).toLowerCase()` (функция транслитерации кириллицы, не-буквы в `_`).

## 2. Источник элементов «Списка (поиск, чекбокс)» — 2 варианта с радиоточкой
Секция «Данные» редактора фильтров:
- радио **«Источник: SQL-запрос | Таблица (id, name)»** → пишется в `itemsKind: 'query' | 'list'`;
- SQL — как сейчас (редактор + база + проверка);
- **Таблица** — грид id/name с добавлением/удалением строк (cell-editing), данные пишутся в `config.items` напрямую (массивом, без JSON-текста); при выборе радиоточкой SQL-вариант остаётся в конфиге, но не действует.

## 3. var — единый контракт SQL (фронтенд)
- `report-config.ts`: `FilterField.var` (из toolbar-конфига фильтра).
- `report-view buildPayload`: если у поля есть var — значения кладутся **по var**: диапазон → `payload[var[0]]=start, payload[var[1]]=end`; список/скаляр → `payload[var[0]]=значение`. Без var — по имени поля (обратная совместимость).
- Go-бэкенд без изменений: общая легаси-интерполяция подставит скаляры (даты — без кавычек, кавычки ставит SQL), списки — как сейчас.

## 4. Миграция `11_prototype_groups.sql` (каталог + отчёты + запросы)
- **var в каталоге**: ПериодМесяцы→[m_start,m_end], ПериодДни→[d_start,d_end], Набор_ЛС→[n_start,n_end], Фериод→[m_start,m_end] (проверив отсутствие конфликта в отчёте-носителе; иначе уникальный var), ФОНД→[fond], УК→[uk], УКП→[ukp], ПОСТ→[post], РасчетыеМесяцы→[raschetesymesyacy] (в SQL не используется — безопасно).
- **Замена placeholder в `reports.query_text`, `report_query.sql_text`, `report_query.filter_names`** (кавычки добавляются для дат, т.к. новая схема вставляет значение без кавычек):
  - `{ПериодМесяцы_start}` → `'{m_start}'`, `{ПериодМесяцы_end}` → `'{m_end}'`, `{perStart}`/`{perEnd}` → то же;
  - `{ПериодДни_start/end}` → `'{d_start}'`/`'{d_end}'`;
  - `{Период_start/end}` → `'{m_start}'`/`'{m_end}'` (если в отчёте нет ПериодМесяцы);
  - `{ФОНД}`→`{fond}`, `{УК}`→`{uk}`, `{УКП}`→`{ukp}`, `{ПОСТ}`→`{post}` (кавычки в SQL сохраняются как есть);
  - `{РасчетыйМесяц}` и `{БД}` — НЕ трогаем (legacy-типы вне новой таксономии).
- Идемпотентно: REPLACE по токенам, повторный прогон безвреден.
