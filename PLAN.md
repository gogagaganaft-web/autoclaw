# План: GOREPORT → Vue + MSI, состояние в MS SQL

Версия 0.2 от 2026-10-23. Заменяет v0.1: написана по фактам чтения `C:\AUTOCLAW\*`,
а не по общему описанию. Детали — в [docs/inventory.md](docs/inventory.md) и
[docs/state-schema.md](docs/state-schema.md).

---

## 1. Что изменилось против первой версии плана

| Было в v0.1 | Стало по факту |
|---|---|
| «Портировать Go-сервисы» | Их **не надо портировать** — 4 бинарника на Gin уже работают, служба Windows и systemd-юниты есть |
| «Нужен Go-gateway» | Достаточно **nginx**: один вход, снятие CORS, порты наружу не торчат |
| «Состояние — новый слой» | Состояние уже есть, но в 3 местах: два файла на пользователя + `queries.json` в CWD процесса |
| «Авторизация условная» | Авторизации в Go **нет вообще**; вход делает PHP/Bitrix, API открыт |
| «Фронт на Vue по шаблону» | `msi-vue` — это шаблон DevExtreme с фейковым логином; переносить надо 28 модулей `msi-js` |
| «Виджетов нет» | Библиотека MSI (`atom.js`) уже собирается и уже используется легаси-фронтом |

Главный вывод: **центр тяжести — фронт и авторизация**, а не серверная часть.

## 2. Что чинится в первую очередь (до новой функциональности)

| # | Дефект | Риск | Действие |
|---|---|---|---|
| D1 | `/api/save-file` пишет по абсолютному пути, `/api/load-file` читает любой файл | Запись в ФС под `www-data`, чтение `.env` с паролями БД | Запретить абсолютные пути, оставить только резолв внутри data-каталога; закрыть порты для внешних адресов |
| D2 | Те же эндпоинты без аутентификации | Подмена статики сайта | Входит в D1 + nginx |
| D3 | `queries.json` пишется в CWD | На Linux молча не сохраняется | Перенос в БД (`app_query`) |
| D4 | Запись без temp+rename и блокировки | Порча файла при параллели | Уходит вместе с файлами |
| D5 | Состояния в веб-корне | Логины и фильтры доступны по URL | Уходит вместе с файлами |
| D6 | `Authorization` не разрешён в CORS на 7501 | JWT сломает preflight | CORS больше не нужен: всё через один origin |

D1–D2 рекомендую закрыть **на проде отдельным патчем в ближайшее время**, не дожидаясь
переписывания: это 10 строк и снимает запись в произвольное место. Требует вашего согласия
и окна — прод я без команды не трогаю.

## 3. Целевая архитектура

```
                 ┌──────────────── nginx (TLS, один origin) ────────────────┐
Браузер ──HTTPS──►  /                → dist Vue (SPA)                       │
                 │  /api/exec/*     → 127.0.0.1:7501  (execute)             │
                 │  /api/report/*   → 127.0.0.1:7502  (report)              │
                 │  /api/preload/*  → 127.0.0.1:7503  (preload)             │
                 │  /api/multi/*    → 127.0.0.1:7504  (multi)               │
                 │  /api/state/*    → 127.0.0.1:7505  (state, новый)        │
                 │  /auth/*         → 127.0.0.1:7506  (auth, новый)         │
                 │  /auth/whoami    → PHP/Bitrix (внешняя зависимость)       │
                 └──────────────────────────────────────────────────────────┘
```

Почему префиксы, а не просто `/api/*`: у 7502 и 7504 **совпадают пути** (`/api/report/init`,
`/page`, `/distinct`, `/close`, `/export`, `/export/status`, `/export-download`, `/mem`).
Плоское пространство имён невозможно — нужен префикс на сервис со strip.

Почему nginx, а не Go-gateway: nginx уже стоит перед сайтом, умеет TLS и `auth_request`;
отдельный бинарник добавил бы третью точку отказа без выгоды.

### Новые сервисы

| Сервис | Порт | Ответственность |
|---|---|---|
| `state-svc` | 7505 | CRUD состояний по таблицам из `docs/state-schema.md`, версии, история, импорт JSON |
| `auth-svc` | 7506 | Провайдеры `dev` / `bitrix24` / `keycloak`, нормализация ролей, сессия, аудит |

Оба — те же приёмы, что в существующем коде: Gin, `go-mssqldb`, `.env`, `internal/service`.

### Фронт

- База — `msi-vue` (Vue 3, Vite 8, pnpm 11), но **`devextreme-vue` из шаблона не используется**:
  виджеты берём из MSI (`atom.js`), как в легаси. Это ваше решение по п.5, фиксирую как принятое.
- Переносим 28 модулей `msi-js` (`DataGridRenderer`, `PivotGridRenderer`, `DashboardRenderer`,
  `MapRenderer`, `StatisticRenderer`, `ExcelPivotGridExporter` и т.д.) в компоненты Vue.
- DevExtreme остаётся только как источник themes/icons на переходный период.
- Маршруты — `createWebHashHistory` уже в шаблоне, менять не нужно (прод отдаёт статику из webroot).

## 4. Состояние: что и куда переезжает

Подробно — `docs/state-schema.md`. Кратко: 6 таблиц + история.

| Было | Стало |
|---|---|
| `<login>_views.json` → `reports[key].current` | `app_report_view` |
| `…variants[mode][]` | `app_report_variant` (+ `is_active`) |
| `<login>_rpt.json[]` | `app_user_report` + `app_user_report_view` |
| `queries.json` (CWD процесса) | `app_query` |
| — | `app_state_history` (снимок на каждое изменение) |

Три правила, которые закрывают текущие дефекты: владелец берётся **только из токена**;
пути в ФС больше не адресуются; запись идёт с `If-Match: <version>` и `409` при конфликте.

JSON остаётся только внутри `filters_json / pivot_json / dashboard_json / state_json /
fields_json` — это лист конфигурации виджета, его схема меняется вместе с UI.
Нормализованы сущности и связи; спорных полей не остаётся.

## 5. Идентичность

```
auth-svc
 ├── dev      → логин из DEV_USER (по умолчанию — имя пользователя Windows), роль из конфига
 ├── bitrix24 → проверка сессии через PHP-эндпоинт /auth/whoami, роли из групп портала
 └── keycloak → OIDC code flow, realm/client roles
        ↓
   внутренний JWT { sub, login, roles[], provider } + сессия в httpOnly-cookie
```

**Внешняя зависимость, без которой Bitrix-вход не сделать:** Go-сервисы не видят сессию
Битрикса — она живёт в PHP. Нужен небольшой эндпоинт на стороне портала (`whoami`: логин,
группы, для валидной сессии), либо договорённость о подписанном токене, который выставляет
PHP при рендере страницы. Это работа на вашей стороне (PHP-разработчик/админ портала),
сроки зависят от неё.

Роли нормализуются в один справочник (`app_role`, `app_user_role`), сервисы видят только
`roles[]` — ни «группы Битрикса», ни «realm roles» в код не протекают.

## 6. Окружения

**DEV (Windows 10).** MS SQL 2022 в Docker — уже поднят, БД `kand` с прод-данными.
Сервисы в консольном режиме, установка как службы — отдельным прогоном перед релизом.
Vue — `vite dev` с проксированием префиксов на localhost, чтобы пути совпадали с прод.

Расхождение, которое надо закрыть: в дев-`.env` заданы только 4 БД из 18. Для проверки
отчётов по остальным нужны либо заглушки, либо доступ к их серверам.

**PROD (Debian).** Схема служб сохраняется как есть (`/opt/goreport`, `www-data`,
`EnvironmentFile`). Добавляем: релизные каталоги `releases/<version>/` + симлинк `current`,
откат переключением симлинка, отдельные юниты для 7505/7506.

## 7. Этапы

| # | Этап | Длит. | Критерий готовности |
|---|---|---|---|
| 0 | Инвентаризация | готово | `docs/inventory.md`, `docs/state-schema.md` |
| 1 | Скелет: `state-svc` + миграции + импорт + nginx-префиксы | 2 нед | Импорт прод-файлов в БД, dry-run совпадает построчно; `state-svc` отвечает 200/409 по контракту |
| 2 | Каркас Vue + MSI, вход-заглушка, один экран (грид + фильтры) на новых API | 2 нед | Экран отдаёт те же данные, что легаси на тех же фильтрах (сверка скриншотами/выгрузкой) |
| 3 | Перенос остальных экранов: сводная, дашборды, карта, статистика, экспорт | 4–5 нед | 28 модулей покрыты; e2e-сценарии зелёные; паритет по выгрузкам Excel/PDF |
| 4 | Идентичность: dev → auth-svc → Bitrix whoami → Keycloak | 2 нед | Вход обоими провайдерами на stage; таблица маппинга ролей подписана владельцем |
| 5 | Закрытие D1–D6, единые `/healthz` `/readyz`, структурные логи | 1 нед | Сканер не находит записи вне data-каталога; порты слушают только 127.0.0.1 |
| 6 | Пакетирование и деплой | 1 нед | Откат на предыдущий релиз < 5 мин, проверено |
| 7 | Пилот и переключение | 2 нед | Параллельная работа, чек-лист cutover, дежурство |

Итого **14–16 недель** при одном разработчике плюс тестировщик на этапах 3–7.
Этап 3 — доминирующий; его точная длина станет ясна после этапа 2, когда будет видно,
насколько API MSI совпадает с DevExtreme в местах, где легаси использует тонкие настройки.

## 8. Риски

| Риск | Влияние | Мера |
|---|---|---|
| Паритет фронта: 28 модулей на DevExtreme-специфике | Срок этапа 3 | MSI собран из DevExtreme с тем же API (`new MSI.ui.dx…`), поэтому перенос — пере-обвязка, а не переписывание; e2e-сравнение на реальных отчётах |
| Bitrix-сессия недоступна из Go | Блокирует прод-вход | PHP `whoami` — внешняя зависимость, начинать согласование на этапе 1 |
| Keycloak на MSSQL | Блокирует второй вход | Spike в этапе 1: поднять на тестовой БД, проверить драйвер/коллацию |
| 18 БД, в деве только 4 | Не проверить часть отчётов | Заглушки + доступ к тестовым копиям, список приоритетных отчётов от вас |
| Кириллические имена таблиц/колонок (`stack.[Виды работ]`) | Ошибки экранирования | Правило: все идентификаторы в квадратных скобках, тест на каждом новом запросе |
| Прод-патчи до переезда | Риск регрессии | D1–D2 отдельным минимальным патчем в согласованное окно, с откатом |
| Секреты в `.env` и в `app_prod.js` (ключ карт) | Утечка | Ротация ключей после закрытия D1, вынос в конфиг окружения |

## 9. Что нужно от вас

1. **Прод-`.env`**: перечень серверов/баз/пользователей для 18 БД (значения паролей — не в чат,
   достаточно имён и того, что доступ будет выдан).
2. **Bitrix**: кто владелец PHP-части и можно ли добавить `whoami`; как сейчас формируются
   `window.USER_LOGIN` и права.
3. **Роли**: перечень и владелец модели (сейчас есть только клиентский флаг редактора).
4. **Keycloak**: версия, realm, клиенты, требования к MFA/федерации с AD.
5. **`Windows.User`**: константа или `os.Getenv("USERNAME")`.
6. **Прод-nginx/PHP**: конфиг статики и как устроен `/auth/`.
7. **История состояний**: нужна ли (влияет на объём `app_state_history` и на UI конфликтов).
8. **Приоритет экранов** для этапа 3: какие 3–5 отчётов критичны первыми.
